# EIP-7702 counter lab

Branch: `feat/partner-aa-7702`, based on the v0.9 AA implementation.

Live devnet demo: <https://partner-7702-demo-lab.up.railway.app/aa>.

The page at `/aa` has two actions:

1. **Activate 7702** previews fees, then signs and sends a type-4 transaction from
   the EOA to itself. The EOA pays the transaction, including DogeOS data fees.
   Its authorization nonce is the transaction nonce plus one.
2. **Increment with AA** previews fees, then signs an EIP-712 UserOperation.
   Alto submits it to canonical EntryPoint v0.9 and is reimbursed by the same EOA.

The EOA address does not change. Assets and DOGE already at that address stay
there. Assets in an older, separate SimpleAccount are not moved.
There is no factory deployment, paymaster or gas sponsorship in this flow.

## Wallet scope

The published DogeOS SDK provider handles transaction and typed-data signing,
but its reviewed embedded-wallet adapter does not expose 7702 authorization
signing. Viem's `signAuthorization` also requires a local signing account;
it does not implement a generic JSON-RPC wallet method.

This demo therefore creates a **disposable browser account**. Its private key
stays in this tab's session storage and is never sent to the backend. Reloads
retain it; closing the tab can lose it. Use about 1 devnet DOGE, not a valuable
account. The activation path rejects balances above 2 DOGE. The SDK provider is
not initialized on the lab page, and no Google/X wallet is silently delegated.

A production SDK integration needs an explicit supported authorization-signing
API and a wallet confirmation that identifies the delegated implementation.
Do not substitute `personal_sign`, assume an invented RPC method exists or
advertise arbitrary delegation support in MetaMask/Rabby without testing it.

The delegate is the unmodified upstream final-v0.9 `Simple7702Account`, built
with pinned dependencies and bound to canonical EntryPoint. The browser pins
the EntryPoint, delegate and counter runtime hashes independently of the API's
manifest. This is an experiment, not a reviewed production wallet rollout.

## Network and persistence

Devnet RPC: `https://rpc.devnet.doge.xyz`. Chain ID: `6281971`.
Genesis: `0x4d6ef3d0349760195375877b4b3d9c0a5107c6df559e075b67e95d48962be868`.

Chikyū currently shares the chain ID but has a different genesis. Both server
and browser verify genesis before signing or submitting. Use dedicated devnet
keys: an authorization signature itself does not include a genesis hash and
can be replayable on a different network sharing the same chain ID and nonce.

Activation is persisted as the exact signed transaction before broadcast.
An ambiguous response or reload recovers that same transaction, rather than
signing another authorization. Success checks the receipt type, sender,
destination, expected `ef0100` delegation and confirmations. A reverted
execution can leave delegation active; the UI checks actual code separately.

The AA operation has its own persisted ID/hash, nonce and receipt verification.
Simple7702Account signatures have no onchain expiry. Revocation does not by
itself erase outstanding signed UserOperations; re-delegation can make an
unconsumed signature usable again. The demo never discards an ambiguous send.

## Run locally

Node.js 24+ is required. Install root, `aa/` and `web/` dependencies with
`npm ci` in each directory; install Playwright Chromium for the browser check.

```sh
# Terminal 1, from aa/
npm run demo:local

# Terminal 2, from web/
npm run build
AA_API_URL=http://127.0.0.1:4342 WEB_ORIGIN=http://127.0.0.1:5191 npm run start -- --hostname 127.0.0.1 --port 5191

# Terminal 3, from repository root/
npm run test:browser:7702
```

The fixture binds Anvil, Alto and its API to loopback only. Browser validation
labels it as a local simulation. The browser test refuses any chain other than
31337 and funds only through Anvil's test RPC. Stop the fixture after testing.
Each fixture run retains its own state in `aa/.runtime/local-7702/run-*`, so a
new local genesis cannot accidentally reuse an earlier run's operation state.

## Deploy to devnet

Use a dedicated ignored private JSON file containing `deployerPrivateKey` and
`executorPrivateKey`. Its executor must match the configured devnet executor.
Do not reuse testnet wallet keys.

```sh
# From aa/; default key path is .runtime/devnet-keys.private.json
npm run deploy:devnet
npm run deploy:devnet -- --apply
```

The first command only quotes costs. The second verifies canonical EntryPoint,
deploys the delegate, counter and Alto v0.9 simulation contracts, funds the
executor with 2 DOGE if necessary, and writes a verified manifest after receipts.
Signed transactions are checkpointed before broadcast; retries reuse the exact
transaction. Each deployment has an 8 DOGE fee cap and uses compressed RLP for
the Galileo oracle. The latest dry run estimated about 0.36 DOGE in fees plus
2 DOGE executor funding; costs change with the network.

The initial deployment received 5 devnet DOGE at
`0x97774C0981FBD6A57b8f9188Cdfa3885611F1844`, assigned 2 DOGE to the executor
and 1 DOGE to the disposable browser test account. Deployment and executor
funding fees totaled `0.449560705627664044 DOGE`, including one reverted
PimlicoSimulations creation. That creation exhausted the former 3,000,000 gas
limit; the script now allocates 7,000,000 to both simulation deployments.
Its confirmed failed receipt was archived before deploying the replacement.
The browser funding transfer also incurred its own small network fee.

Deploy backend and web as **separate new lab services**, with a separate state
volume. Backend: `BUNDLER_EXECUTOR_PRIVATE_KEY`, `AA_STATE_DIR=/data`,
`PORT=4341`, `WEB_ORIGIN`. Web: `AA_API_URL` pointing to that backend and
`WEB_ORIGIN` matching its public origin. The 7702 page needs no SDK client ID.
Do not repoint the existing Chikyū demo or its executor/state at devnet.

### Reproduce the live browser check

Use a fresh, dedicated devnet browser account, funded with about 1 DOGE.
The private JSON file must contain `browserPrivateKey` or `privateKey`.

```sh
# From repository root. This signs and spends real devnet DOGE.
WEB_URL=https://partner-7702-demo-lab.up.railway.app \
TEST_KEY_FILE=aa/.runtime/devnet-keys.private.json \
npm run test:browser:7702:devnet
```

The test verifies the exact devnet genesis, uses the hosted buttons, checks both
receipts and account fee accounting, and saves a private checkpoint under
`aa/.runtime/`. Keep it when resuming the same test: it retains the activation
and operation identity across interrupted runs. Public proof and a screenshot
are written under `test/results/`. The test uses only the browser key; it never
initiates a funding transfer or calls Anvil methods.

## Bundler scope for an operator

Alto is pinned to 0.0.21 and its v0.9 simulations. Delegation is a separate
wallet-paid transaction, so no `eip7702Auth` is accepted inside UserOperations.
Normal subsequent operations use the already-delegated EOA.

The public DogeOS RPC does not offer `debug_traceCall`; this restricted counter
demo uses `safe-mode=false`, one executor, loopback-only Alto and an allowlisted
API. It is not a general public bundler or a production operating configuration.
A general service needs compatible tracing, validation, mempool policy,
executor funding/nonce management, monitoring and capacity/recovery work.
The account pays both execution and DogeOS L1 data fees; preserving the Galileo
zstd fee model is required to avoid subsidizing or overcharging users.
